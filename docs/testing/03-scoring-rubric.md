# read-pal 浏览器实际使用测试 · 评分标准与发布门禁（Scoring Rubric）

> 配套：[01 总体方案](01-master-plan.md)｜[02 测试用例](02-test-cases.md)｜[04 物料指南](04-materials-guide.md)
> 版本：v1.0（2026-08-30）。与 `docs/browser-test-plan.md` 自动化评分同一哲学：加权得分制、模块 ≥85 通过 / ≥60 降级。

## 1. 评分总则（三层模型）

```
用例级（单条判定 × 优先级权重） → 模块级（16 模块得分） → 产品级（加权总分 + 硬门禁）
```

- **分数回答"质量多高"**，门禁回答"能不能发"；两者独立计算，**门禁一票否决**（见 §7）。
- 所有得分必须可复算：`execution-record.csv` 为唯一数据源，报告中的每个数字都能从记录表重算出来。

## 2. 用例级判定定义

| 结果 | 分值系数 | 判定条件 | 证据要求 |
|---|---|---|---|
| `PASS` | 1.0 | 全部预期达成，无任何异常 | P0 必须截图；其余抽检 |
| `PASS_WITH_ISSUE` | 0.5 | 主流程达成，但存在**不影响主流程**的瑕疵（已提 S3/S4 缺陷） | 截图 + 缺陷单号 |
| `FAIL` | 0 | 任一关键预期未达成（已提 S1/S2/S3 缺陷） | 截图/录屏 + 缺陷单号 |
| `DEGRADED` | 不计入分母 | **外部依赖**不可用导致无法执行（LLM Key 无效、SMTP/OAuth 未配置、pgvector 缺失），且产品侧降级行为本身合格 | 降级表现截图 + 依赖说明 |
| `BLOCKED` | 不计入分母 | 被测功能无法到达（如前序 P0 失败、环境故障），非产品缺陷 | 阻塞原因 + 责任人 |

**判定纪律**：

1. `DEGRADED` 只允许用于外部依赖；**产品自身的降级表现差（如白屏、永久 loading）记 FAIL**，不记 DEGRADED（例：CHAT-14 本身就是在测降级表现，其失败就是 FAIL）。
2. 同一缺陷导致多条用例 FAIL 时，每条照实记 FAIL（不合并提分），但缺陷单只提一张并互相引用。
3. `BLOCKED` 的上游用例修复后必须回头补测，否则该模块不得出具得分。

## 4. 模块得分

```
模块得分 = Σ(用例分值系数 × 用例权重) / Σ(计入分母用例的权重) × 100
```

| 模块得分 | 结论 |
|---|---|
| ≥85 | 模块通过（PASS），与自动化场景阈值一致 |
| 60–84 | 模块降级（DEGRADED）：可发布但需列明风险 |
| <60 | 模块失败（FAIL）：对应功能面不可发布 |

## 5. 产品得分与等级

```
产品得分 = Σ(模块得分 × 模块权重) / 100
```

| 等级 | 产品得分 | 发布建议 |
|---|---|---|
| A | ≥90 | 达到发布标准（仍须过 §7 门禁） |
| B | 80–89 | 有条件发布：S2 清零或有评审通过的规避方案，风险清单随发布说明 |
| C | 60–79 | 不对外发布；可灰度/内部使用，限期修复后重测 |
| D | <60 | 不可发布，回归开发 |

**抽样规则（计分口径）**：P0/P1 全量执行；P2 抽样 ≥70%（按模块内均匀抽取，含全部条件用例）；P3 抽样 ≥30%。未抽到的 P2/P3 不计入分母；**抽到的必须出结果，不允许跳过**。

## 6. 缺陷定级（S1–S4）

| 级别 | 名称 | 判定标准 | read-pal 示例 | 处置要求 |
|---|---|---|---|---|
| S1 | 致命 | 主流程不可用 / 数据丢失 / 安全越权 / 白屏崩溃 | 注册或登录不可用；上传全类型失败；划线刷新即丢；A 能看到 B 的数据；书名 XSS 实际执行 | 立即中断该模块测试并上报，24h 内修复 |
| S2 | 严重 | 主功能明显错误但可绕行 / 核心体验严重受损 | 进度不持久化；AI 流式无输出但重试可通；删除书后路由白屏；暗色下阅读器不可读 | 发版前必须修复或评审通过规避方案 |
| S3 | 一般 | 次要功能错误 / 局部体验问题 | 排序个别错误；筛选计数不准；文案缺译；样式错位 | 列入近期迭代 |
| S4 | 轻微 | 优化建议 / 极低频边角 | 动效卡顿；提示不够友好 | 记录跟踪 |

定级由测试负责人裁决；开发可申诉一次，须提供"用户影响可忽略"的证据。

## 8. DEGRADED 豁免规则（外部依赖）

| 规则 | 内容 |
|---|---|
| 允许的依赖 | LLM 供给（Key/配额）、SMTP、Google OAuth、pgvector、对象存储 |
| 单模块上限 | 模块内 DEGRADED 占比 >30% 时，该模块**不出具得分**，标注"依赖修复后重测"，其权重从产品总分中剔除并重新归一 |
| 产品上限 | 全局 DEGRADED 占比 >20% 时，本轮验收结论只能给"环境受限，无法定级"，不得给 A/B |
| 举证责任 | 标 DEGRADED 必须附依赖不可用证据（如 401/配额报错截图）+ 产品降级表现合格证据 |

## 9. 自动化与手工双轨关系

- **自动化（browser-tests.mjs）是门禁（G4），不计入手工产品得分**——其 7 场景是 02 用例集的子集，计入会重复加权；
- 自动化发现问题→映射到 02 对应用例记 FAIL（映射关系：S1→AUTH、S2→UPLD/LIBR、S3→READ、S4→ANNO、S5→CHAT、S6→MEMB/STAT、S7→XCUT）；
- 每日例行跑自动化；发版/验收时跑全量手工。自动化脚本本身的缺陷（选择器失效等）单独提单，不污染产品分。

## 11. 评分示例（可复算）

设 M4 阅读器执行 20 条：P0×5 中 4 PASS、1 FAIL（READ-06 进度不持久化，S2）；P1×8 全 PASS；P2 抽 5 条：4 PASS、1 PASS_WITH_ISSUE（S3）；P3 无。

```
分子 = (4×4) + (3×8) + (2×(4 + 0.5)) = 16 + 24 + 9 = 49
分母 = 4×5 + 3×8 + 2×5 = 20 + 24 + 10 = 54
M4 得分 = 49/54 × 100 ≈ 90.7 → 模块 PASS
```

注意：即便 M4 得 90.7，READ-06 属 P0 FAIL，直接触发 **G1 不满足 → 不可发布**。这正是"分数之外必须有门禁"的原因。
